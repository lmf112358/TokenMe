# TokenMe 项目检查 · 2026-10-19

结论：项目已经完成本地 MVP 的主要功能链路，当前是 `0.2.0.dev4` 开发预览，可进入小范围真实用户试用。尚未达到“多平台均充分验证、普通用户开箱即用”的正式发布状态。这里按源码、构建和本机实测判断，不用未经定义的完成百分比。

## 本轮推进

- “混沌涌现”从独立设计稿接入正式报告，成为默认分享样式；保留材质经典切换。
- 同一统计模型驱动两套样式；累计/月度、两画幅、二维码、空数据禁用导出均保留。
- 绘图的唯一源文件迁入 `token_footprint/share-cyber.js`；设计预览直接使用它，不维护第二份产品绘图实现。
- 新模块嵌入单文件离线 HTML，进入 wheel；源码包补齐设计预览 JS 和浏览器验证脚本。
- 增加生成真实报告 HTML 后再打开浏览器的集成验证；修复 CI 只运行部分 Node 测试的遗漏，补充浏览器任务。
- 本地版本推进到 `0.2.0.dev4`。没有创建发布 tag 或推送；本轮尚未获得远端 CI 通过证据。

## 验证结果

1. `python -m unittest discover -s tests -q`：76 项通过。
2. `node --test tests/test_share_card.cjs tests/test_tokscale_card.cjs`：13 项通过。
3. `scripts/verify_report.cjs`：由 Python CLI 生成五等级报告，检查 5 等级 × 2 样式 × 2 周期 × 2 画幅 × 2 二维码状态，共 80 组。五次实际 PNG 下载逐字节等于点击时预览；空周期禁用导出，360 px 页面无横向溢出，没有浏览器异常和联网请求。
4. 新样式五张方图经 ZXing 解码，1080 / 720 / 540 px、JPEG 85 质量共 15 组，均返回项目公开入口。未做实体手机或社交平台上传测试。
5. 用已有真实历史账本的 27,244 条规范化记录重建报告，包含 Codex、WorkBuddy、Claude Code、Pi。检查默认新样式、累计/月度、两画幅和 360 px 布局；本轮未重新扫描来源日志，也未读取官方账号接口。
6. wheel/sdist 构建及 `scripts/verify_wheel.py` 的仓库外隔离安装通过，包含新绘图资源、Tokscale 合成导入和带空格路径 Agent 安装。

个人账本、真实报告和截图只保留在忽略目录 `.local/cyber-integration/`，不进入公开设计包、源码包或 README。

## 发布前优先缺口

| 优先级 | 需要补齐 | 验收标准 |
| --- | --- | --- |
| P0 | 固定可发布版本并完成远端检查 | 对确切提交运行 Windows/macOS/Linux 测试、浏览器检查与隔离安装；发布包来自该提交。对未验证平台保留清晰标识 |
| P0 | 真实来源对账 | 先对核心使用平台逐日核对样本与源工具；记录版本、时区、缓存口径、日志保留范围和差额原因。Tokscale/Cursor/TRAE 等按 `platform-gaps.md` 逐项关闭缺口，不能用合成测试替代 |
| P1 | 首次使用体验 | 让至少 5 名目标用户独立完成安装 → 发现来源 → 生成 → 保存/扫码，记录卡住位置。覆盖无 Python、空记录和导入冲突；明确哪些问题需要安装器或引导改造 |
| P1 | 跨设备分享验证 | 至少两类手机相机识别，实际经过目标社交平台压缩后扫码；检查字体、保存路径和缩略图等级辨识 |
| P1 | 数据纠错和范围说明 | 当前通过 CLI 导入/修订和来源拒绝保护账本；仍缺面向普通用户的纠错、账号/设备范围与导入批次管理界面 |
| P2 | 传播入口与视觉一致性 | 二维码当前进入 GitHub；独立落地页尚无。报告页主体仍采用原浅色风格，分享卡已换新；如要求全产品统一视觉，需另做报告页设计 |

## 后续阶段，不作为当前 MVP 必做项

无 Python 的独立桌面安装器、账号云同步、普通网页聊天全量接入、跨设备自动合并、作品关联与第三方成果验证都尚未实现。是否投入应根据首轮试用反馈排序。没有可靠 Token 合同的平台继续显示待接入；不使用 Credits、次数或估算冒充原生 Token。

## 下一步顺序

先完成核心平台真实对账与小范围试用，再固定发布提交并跑远端检查，随后发布 v0.2。这阶段的重点是让“安装、数字可信、分享成功”有真实证据；继续增加卡片风格的收益已低于这些工作。
