# 本地历史库 v1

> v0.2 更新：可只读读取 v1，首次写入前自动保存 `<原库名>.pre-v2.sqlite3`，再事务升级至 v2。v0.1 程序不能直接读取升级后的 v2，请使用升级前备份回退。`snapshots` 保存聚合快照、扫描变化和来源诊断；不会复制原始对话。重复扫描无记录变化时不新建快照。`backup` 完整保存档案；原 JSONL 导出只保留记录，不能迁移原快照。下文是 v0.1 基线规则，其去重与数据口径继续适用。

`scan` 将白名单 UsageRecord 写入 `<out>/history.sqlite3`。SQLite 以 `record_id` 为主键，整批事务提交；错误回滚本批，已有历史不受影响。数据库版本为 `PRAGMA user_version=1`，未知版本和其他 SQLite 文件均拒绝使用。

## 身份与更新

- Codex：timestamp + cumulative counters 指纹，对保留原时间戳的重放去重。同 ID 请求增量计数冲突时中止。被重写时间戳的历史仍可能重复；跨设备/账号自动对账尚不支持。
- WorkBuddy：trace ID 指纹。结束时间较新的快照替代旧值，较旧快照忽略；同结束时间的新观测可作为修订。
- ccusage：source + day 指纹。重新导入替代整个桶，不相加；最后导入是权威版本，用户需保证完整性。
- Tokscale graph：带导入标记的 source + day 指纹；按平台合并模型后替换整日桶。与 ccusage/原生采集同平台互斥，备份恢复和临时扫描也检查。零值修订保留账本记录但不计活跃日；详见 [Tokscale 导入](tokscale-import.md)。
- native 与 daily_bucket 不能覆盖同一 source，检查包含已有历史与本次输入。
- `--sources` 选择要更新的 collector，报告仍读取全库；日志消失不会删除历史。

请求级记录可按不同固定偏移重算；存在日桶时必须保持导出时的 `--offset`。每个库仅服务一个人、一套可排除重叠的数据来源。

## 可移植备份

`export --out <path>` 导出 JSONL，`scan --sources none --import-records <path>` 恢复。每行保留记录标识、来源、模型、带时区时间戳、计数、证据和粒度；额外字段不导入。整份文件验证通过后再写事务。

`records.jsonl` 是完整历史快照，含个人统计，不能上传到公开问题或仓库。关闭程序后也可自行复制 SQLite 文件；日常迁移优先使用 JSONL。导出不包含账号摘要或昵称，账号摘要需单独保管。

v0.1 不提供单条删除界面、自动云备份或历史 schema 迁移。需要全新范围时指定新输出目录/新 `--store`，保留旧库备份。删除原日志不会删除已入库记录。

`report` 只读打开历史库，缺失库不会被创建；数据库路径不能与输出文件重叠。数据库沿用操作系统用户文件权限，不额外加密。磁盘损坏需从用户备份恢复。SQLite 写锁串行提交；请依次生成同一目录的 HTML，v0.1 不保证多个进程同时写报告的文件一致性。
