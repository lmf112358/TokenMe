# 个人 AI 用量统计：接入与口径设计 v0.1

设计日期：2026-10-10。目标是个人网页、App 和桌面订阅用户的开源分享项目。

## 1. 最重要的产品决定

以“使用入口”为接入单位，不以“模型品牌”为接入单位。同一个 DeepSeek 模型可以运行在 DeepSeek App、WorkBuddy、自带 API Key 的客户端和第三方平台。模型名不能确定账单账号，客户端与提供商是两个独立维度。

数据链路：

```text
客户端保留记录 / 官方账号接口 / 用户导出
    → 平台适配器（只提取用量字段）
    → 标准记录 + 来源 + 计数语义 + 覆盖边界
    → 去重与口径校验
    → 本地汇总 / PNG 分享卡
```

联网查询和离线扫描是不同命令。没有中央账号库，不索取各平台密码，不上传 Cookie、Token 凭据或对话。

## 2. 数据接入顺序

1. **官方个人账号用量接口**：有公开文档、允许只读查询且能复用官方认证时优先使用。已验证 Codex app-server `account/usage/read`。摘要的累计值和每日桶可能缺失，不应补零。
2. **客户端本地用量日志**：适用于 Codex、WorkBuddy 等。有真实字段但历史保留、设备覆盖、云任务、异常中断可能不完整；标记为本地记录，不称为官方认证。
3. **官方导出文件**：若包含实际 usage 字段可接入；若只有聊天内容，最多导入对话数量或活动日期，不能还原计费用量。
4. **用户当前登录页面的数据适配器**：后续浏览器扩展仅在指定平台且由用户主动触发时运行。先验证页面是否提供原生 usage；只提取时间、模型、请求 ID、用量等允许字段。没有公开接口时标记“页面适配 / 非稳定协议”，记录适配器版本，不宣称长期可靠。
5. **内容估算**：如未来需要，应单独标为“可见文本估算”，不计入实测 Token 主榜。系统提示、历史重发、工具调用、隐藏推理等无法从可见聊天恢复。

当前原型实现 1、2，以及 ccusage 本地导出桥接；3、4 的各个平台适配尚未实现。

## 3. 个人平台矩阵

| 平台入口 | 已确认的读取线索 | 目前缺口 / 下一步 |
|---|---|---|
| Codex 桌面/CLI | 本地 token_count；官方账号摘要接口已在此机返回数据 | 账号摘要覆盖产品、日界线、缓存定义需补充确认；不与日志相加 |
| ChatGPT 普通网页/App | 与开发者 API 是不同账本；目前不能认定 Codex 摘要就是普通聊天全量 | 在账号 UI/官方文档核对统计范围 |
| WorkBuddy 桌面 | 本机 trace 的 totalInputTokens / totalOutputTokens / totalCachedTokens | trace 覆盖可能不含全部子代理；后续核对 transcript，避免双计 |
| WorkBuddy 账号网页 | 官方说明提供积分明细 | 积分不固定换算 Token；可后续作为独立资源指标 |
| Kimi 网页/App | 本轮未确认公开的全账号 Token 接口 | 检查用户登录页面及导出格式；不以 Moonshot API 账单冒充 |
| Kimi Code | 官方说明有 session 日志；ccusage 支持 | 可走导出桥接，不是 Kimi 聊天账号全量 |
| 千问网页/App | 本轮未确认普通聊天的全账号 Token 接口 | 与百炼、Token Plan 分开建 adapter |
| 千问 Token Plan / Qwen Code | 有用量分析说明 / 本地遥测及 ccusage 支持 | 确认实际订阅产品与字段，不能拿 Credits 当 Token |
| DeepSeek 网页/App | 官方支持导出历史对话 | 尚未确认导出包含服务端实际 usage；先检查脱敏 schema |
| OpenAI / Moonshot / 百炼 / DeepSeek API | API 返回 usage 或提供账单/用量查询 | 属于后续独立入口，不替代个人订阅 |

“未确认”意味着当前证据不足，不意味着平台必定没有该能力。

## 4. 统一账本

记录字段包括 `record_id`、`source`、`provider`、`model`、`occurred_at`、`input_tokens`、`output_tokens`、缓存/推理子集、`evidence`、`granularity`。

- **输入 inclusive**：包括普通输入、缓存读取、缓存写入。某来源的 input 不含缓存时，由适配器显式加回；不能靠字段名称猜测。
- **输出 inclusive**：推理属于输出子集；有隐藏推理但未报告时，不自行补值。
- **total = input + output**：不匹配时排除该记录并留下诊断，不静默修正。
- **时间**：原始时间戳保留时区，聚合时使用指定日界线。只有日桶的数据不得伪装成请求级精度。
- **不可换算项**：积分、百分比、订阅金额、图片张数、视频秒数、音频时长。后续作为独立 measure 类型，保持原单位。
- **成本**：真实扣款与 API 等价估值分离；0.1 不生成金额，避免把订阅权益误写成真实支出。

## 5. 去重与来源选择

- Codex 将累计值差分；相同累计快照不再次记账。fork 保留原 timestamp + cumulative 的记录只计一次。计数器回退另记诊断，采用最后一次请求用量。截断日志开始前的累计余额不硬塞到当前日期。
- WorkBuddy 按 trace ID 唯一，已结束 trace 的更新快照替代旧快照。当前不同时累加 trace 与 transcript。
- ccusage 的同源数据与原生 collector 同时导入时拒绝，用户须选择一个来源。
- 官方账号汇总与本地记录有重叠但无法请求级对账，两个视图分开显示。
- 后续需要 `account_alias`、`device_alias`、`origin_request_id` 和 `coverage_scope`。同账户同周期只能选择一条主统计链；账单作为校验视图。不能简单用“优先级更高”覆盖范围不同的数据。
- 当前 Codex 历史去重依赖时间戳及累计快照未被重写；不能宣称对所有版本、导入、跨账号日志都完全可靠。

## 6. 证据与完整度分别表示

| 字段 | 含义 |
|---|---|
| provider_response | 本机向官方客户端接口实时请求所得；公开分享后仍缺少第三方防篡改证明 |
| local_record | 客户端落盘统计，可修改，未与账单核验 |
| estimated（未来） | 从可见内容估算，单独展示 |
| unavailable | 无接入或无可用数据，不是 0 |

证据来源不等于覆盖完整度。主页面显示“已记录”而不是“全平台全部消耗”。缺少全量分母时不捏造“覆盖率 80%”。

## 7. 开源传播界面

首屏是一张可分享的个人使用卡。主卡展示可按相同规则相加的本地明细；官方账号累计作为独立卡片，避免看似漂亮但重复的总量。

当前累计分享图字段：昵称、生成月份、累计 I 量（1 I = 100万原生 Token）、精确 Token 总数、五档材质等级、活跃天数、主要工具与观测范围。输入/输出/缓存明细留在统计区。分享图使用全部保留历史，与统计区月份选择独立。不默认公开模型明细、会话名称或项目内容；不做虚构百分位、信用评级或节省工时。

尺寸、等级门槛与二维码设计见 [分享图设计基线](share-card-design.md)。分享图使用原生 Canvas，预览和导出共用画布，不新增运行依赖。累计历史已通过 SQLite 持久保存；清理源日志不会删除已保存记录，首次扫描前删除的记录不能恢复。具体更新与备份规则见 [历史库说明](history.md)。

## 8. 下一阶段验收

- Kimi / 千问 / DeepSeek：逐个核对个人入口中的原生用量字段；能读到才标“已接入”。若没有实际 Token，独立展示使用次数或等待后续支持。
- WorkBuddy：用受控任务对比 trace、主会话、子代理和积分明细，证明统计覆盖。
- 历史存储：v0.1 已实现 SQLite、稳定身份 upsert、事务回滚、导出恢复；后续扩展来源身份与显式纠错界面。
- 分发：包装桌面应用或安装器，默认本地保存，给出来源选择与可见预览。
- 社交：v0.1 已固定 TokenMe 名称、分享模板和仓库入口二维码；后续验证实际用户分享与手机扫码。真实用户记录不进入源码仓库。
