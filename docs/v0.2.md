# v0.2 · 从用量统计到可追溯的协作档案

状态：`0.2.0.dev1` 开发预览，保留 v0.1.0 稳定版本。

## 产品立意

长期愿景：让人与 AI 协作的经历，成为可以积累、展示和验证的个人信任凭证。Token 是活动记录，不能单独证明成果质量、诚信或履约能力。用量材质与数据证据强度分开表达。

本版落实三件事：Agent 可稳定调用、数字变化可解释、用户有连续档案与月度纪念。用户自愿关联作品和项目、成果验证、外部认可属于后续阶段，不把尚未实现的能力包装成信用认证。

## 开发预览已实现

1. Agent 安装：`scripts/bootstrap.py` 使用隔离虚拟环境安装当前已审查的检出，可选匹配版本的本地 wheel 离线安装。`--check` 只预览计划，`--run` 安装后生成报告。
2. 稳定入口：`doctor --json` 仅读环境与目录；`run --json` 默认使用 `~/.tokenme/report`（可用 `TOKENME_HOME` 指定），不随 Agent 工作目录改变。
3. JSON 协议：`schema_version/ok/command/data`，失败为 `error` 且非零退出；Agent 不必解析中文界面。旧命令不加 `--json` 时保持原输出形状。
4. 本次变化：新增记录/Token、修订记录/Token、重复记录、忽略旧快照、净变化分别返回并在报告中展示。
5. 历史快照：记录内容或统计偏移有变化时保存，重复扫描不重复创建；报告和 `timeline` 展示最近 50 个快照。首次快照建立起点，不伪造先前变化。
6. 迁移与备份：读取 v1 无需迁移；首次写入前生成 `<原库名>.pre-v2.sqlite3`，事务升级到 schema v2。`backup` 完整保留快照，拒绝覆盖既有文件。
7. 月度纪念图：独立选择分享月份；I 量、日期、工具与活跃日采用当月统计，材质仍由累计历史决定，明确显示“累计 Lx”。空月不借用累计数据。

## 不变的边界

仍只支持现有 Codex、WorkBuddy 和 ccusage 导入。账号摘要不叠加；不自动查询账号、不上传记录、不自动打开外部页面。来源目录存在不等于存在有效记录，更不代表完整覆盖。

记录修订可以导致负变化。变化可能来自补录旧日志，不能当成当天新增使用。材质不因选择月份而清零；用量不转换为信用分、效率分或排名。

## 正式发布前

本机验证：41 项 Python 测试、8 项 Node.js 测试通过；本地 wheel 隔离安装及带空格路径的 Agent 安装后运行通过；真实 v1 账本副本迁移、备份与两次快照检查通过；月度两种画幅和 360 px 窄屏检查通过。当前结果来自 Windows 本机，尚未完成此开发预览的远端跨平台 CI。

- 收集不同用量用户对安装、分享和月度纪念的反馈。
- 在更多 Agent 环境中验证安装说明；无 Python 的环境仍需先提供 Python 3.10+。
- 继续验证不同日志版本和真实跨平台客户端。独立落地页、桌面安装器、作品关联与认证尚未包含。
